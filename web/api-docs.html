Obtenir l’accès

Déposez une proposition sur le portail de votre établissement. Après approbation, l’administrateur vous communique la clé API par un canal sécurisé. L’API utilise la même adresse que ce portail. En local, une adresse 127.0.0.1 est accessible depuis le poste qui héberge le serveur.

Pour chaque requête, envoyez la clé dans l’en-tête Authorization: Bearer VOTRE_CLÉ. Une clé en lecture seule permet de consulter les demandes. Pour soumettre ou annuler, utilisez une clé avec droits d’écriture.

Routes disponibles

MéthodeRouteUtilisation
POST/v1/jobsSoumettre un calcul et recevoir son identifiant. Réponse 202.
GET/v1/jobs/{job_id}Consulter le statut ou récupérer les résultats.
POST/v1/jobs/{job_id}/cancelAnnuler une demande en attente ou en cours.

job_id est l’identifiant renvoyé lors de la soumission. Gardez-le pour interroger ou annuler ce calcul.

Lancer un premier calcul

La capsule square-fp16-v1 accepte entre 1 et 4 096 nombres compris entre −200 et 200. Elle calcule leurs carrés en FP16 et renvoie les résultats dans l’ordre d’entrée.

Définissez la variable d’environnement OPEN_NPU_API_KEY dans votre terminal avant d’exécuter l’exemple. Gardez-la hors des scripts partagés et des dépôts.

Prérequis : une clé d’un projet approuvé et un agent NPU compatible disponible pour ce projet.

Télécharger le script de démonstration PowerShell

Le script soumet trois valeurs, attend la fin du calcul et vérifie que le résultat est [4, 9, 16].

PowerShell
Linux ou macOS · curl

Interrogez périodiquement la demande jusqu’à atteindre un état final. Les états queued et running indiquent une demande active. Les états finaux sont done, failed et cancelled.

{
  "id": "aabbcc00112233445566778899aabbcc",
  "status": "done",
  "values": [4, 9, 16]
}

Pour rejouer une soumission après une erreur de réseau, réutilisez la même valeur de l’en-tête Idempotency-Key avec les mêmes données. L’API renvoie le même identifiant.

Capsules signées et calculs par étapes

GET /v2/capsules liste les versions approuvées et leurs contrats de tenseurs. Utilisez la même clé de projet que pour l’API v1.

POST /v2/jobs soumet une version précise. Pour un décodeur, envoyez des identifiants de tokens correspondant au tokenizer du modèle et le nombre maximum de nouveaux tokens.

{
  "capsule": "tiny-decoder",
  "version": 1,
  "tokens": [1, 4],
  "max_new_tokens": 3,
  "distinct_nodes": true
}

GET /v2/jobs/{job_id} renvoie l’état, l’étape et les tokens générés. Avec distinct_nodes, chaque étape exige un nœud distinct. Pour un test sur un seul poste, utilisez false.

verify_results: true fait recalculer chaque étape par un second nœud compatible. Une divergence met la demande en échec. POST /v2/jobs/{job_id}/cancel annule une demande en attente ou en calcul.

Pour une capsule de type tensor, envoyez values à la place des tokens et récupérez la sortie binaire little-endian via GET /v2/jobs/{job_id}/result.

Erreurs et limites

400 ou 415
Vérifiez le corps et l’en-tête Content-Type: application/json à la soumission.
401 ou 403
Vérifiez que la clé est active et autorise l’opération.
404
Vérifiez l’identifiant de la demande et le projet auquel la clé appartient.
409
Vérifiez les règles d’admission du projet, l’état de la demande ou la réutilisation de la clé d’idempotence pour un contenu différent.
429
Le quota du projet est atteint. Attendez le délai indiqué par Retry-After.
